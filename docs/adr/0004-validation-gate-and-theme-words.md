# 程序化分级校验作为硬门禁;主题词按轨道豁免

每篇 **Story** 入库前必须通过 **Validation Gate**(`validateStory`:词表归属、句长上限、生词密度、题目结构)。校验失败直接拒绝入库,人工无法绕过。**Band** 词表之外,每个 **Interest Track** 有一组主题词,在本轨道内豁免「超纲」与「生词密度」。

理由:AI 生成与人工撰写都会无意违反分级约束;把「分级」固化成可执行门禁,是这个核心卖点可信的唯一保证。主题词豁免则是「兴趣轨道」的必然推论——选了恐龙轨道的孩子本就熟悉 `dinosaur`,不该把它算作超纲生词(否则低级别的主题故事几乎无法通过校验)。

## Consequences

- 内容产出是「三层管线」:AI 生成 → 程序校验(本门禁)→ 人工通读发布。批量生成实测产出率约 80%(12/15),不达标的被自动拦下。
- Band 词表划分会随实测持续校准(下放被高估的 A1 词);校准只放宽不收紧,对已通过的 Story 单调安全。
- 校验逻辑有回归测试覆盖(引号切句、所有格专有名词、名字槽位)。

## Considered Options

- **只靠人工审核,不做程序校验**:无法保证分级一致性,且无法规模化。
- **只靠 AI 自检词表**:LLM 不会真的逐词对照词表,不可靠。程序校验才是权威。
